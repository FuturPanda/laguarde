A control loop the whole team can understand.

Agents receive context and a precise boundary. Humans retain the decisions that matter, and recurring feedback becomes durable policy instead of disappearing into one chat.

01 / DEFINE

Capture how your team works

Store code rules, general guardrails, project initialization recipes, and PR review guidelines with revision history.

02 / GATE

Evaluate before acting

The agent declares its intended files, commands, and dependencies. Laguarde returns a decision tied to exact policy revisions.

03 / REMEMBER

Turn feedback into policy

Related corrections converge into a proposal. The agent may suggest; only a human can ratify the next accepted revision.

Four outcomes. No vague “be careful.”

Every evaluated action receives a visible next step, from normal work through explicit human approval to a hard stop.

AllowedProceed inside the declared scope and retain test evidence.
LimitedNarrow, split, or clarify the action before evaluating it again.
ApprovalWait for a human to approve this exact recorded action.
ForbiddenDo not execute. Propose an alternative that avoids the unsafe operation.

Run it where your policies belong.

Run one private local daemon for all of your projects, or deploy one server behind your team’s HTTPS endpoint. Each repository gets its own identity and MCP URL while sharing global policy.

Local MCP with npm

Reuse the local daemon and register the current repository.

npx -y --package laguarde-mcp@0.3.1 laguarde-daemon register --cwd .

Team server with Docker

Good for a shared policy registry on a trusted private network.

docker compose up --build
The honest boundary: MCP makes policy discoverable and decisions auditable. Technical enforcement requires the host agent, command proxy, sandbox, or CI system to make Laguarde a mandatory step before execution.
